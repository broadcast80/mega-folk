# neo-war

Скелет игры на гексовой карте: Babylon.js 9, WebGPU, весь мир на сцене сразу.

Минимальный мир 288×208 = 59 904 гекса; в интерфейсе доступны линейные размеры
1×, 1,5×, 2× и 3×. Вся геометрия рельефа — один меш и один draw call,
вся растительность мира — три draw call на любом количестве деревьев. Ни чанков,
ни LOD, ни стриминга: сначала честный замер, потом оптимизации, а не наоборот.

## Запуск

```text
npm install
npm run dev      # http://localhost:5180
```

Только по `localhost`. WebGPU требует secure context, и по IP-адресу
`navigator.gpu` недоступен даже при живом адаптере.

Для замеров производительности годится только `npm run build && npm run preview`:
dev-сборка добавляет свои стадии и хитчи.

**Молчаливого отката на WebGL нет.** Если запрошен WebGPU и он не поднялся,
страница останавливается с сообщением. Тихий fallback — главный источник
сравнений «WebGPU против WebGL», где на самом деле оба раза был WebGL. Нужен
запасной путь — `?backend=webgl`, явно.

## Управление

| | |
| --- | --- |
| WASD, стрелки | движение (скорость зависит от зума) |
| Q / E | поворот вокруг точки обзора |
| R / F | наклон |
| колесо | зум к курсору, а не к центру экрана |
| ПКМ | вращение и наклон |
| СКМ | панорама |
| Shift | втрое быстрее |
| ЛКМ | выбрать гекс |
| Пробел | следующий ход |
| Esc | снять выделение |

Точка обзора едет по рельефу: её высота берётся с земли под ней, поэтому зум в
долину и зум на вершину оставляют камеру на одной высоте над поверхностью.

## Архитектура

```text
src/
  world/    генерация и геометрия мира — headless, без Babylon и без DOM
  game/     состояние игры — headless, команды и события
  render/   всё, что знает про Babylon
  app/      сборка всего вместе: загрузка, ввод, HUD
```

Правило одно и оно проверяется автоматически (`npm run check:boundaries`):

- `world/` не импортирует ни `@babylonjs`, ни `render/`, ни `game/`, ни `app/`;
- `game/` не импортирует ни `@babylonjs`, ни `render/`, ни `app/`.

Из этого следует всё остальное. Генерация мира запускается в Node (`npm run
bench:world`) и может уехать в Worker без переписывания. Состояние игры меняется
только через `game.dispatch(command)`, а слушатели узнают об изменении через
`game.subscribe` — то же самое сможет делать сеть, реплей и бот, не трогая ни
камеру, ни канвас.

Попадание курсора в мир тоже headless: `surface.raycast` марширует по функции
высоты вместо того, чтобы пикать 360-тысячетреугольный меш рельефа на CPU.

## Генерация мира

Основана на ранней версии из city-folk, но форма мира заменена японской
вулканической дугой: четыре главных острова, цепь малых островов, проливы и
горный позвоночник вдоль суши. Отдельный рельеф внутри берегового контура,
эрозия по Braun & Willett, приоритетная заливка впадин, озёра, водосбор, реки,
биомы по температуре и влажности с орографическим дождём.

| | city-folk | neo-war |
| --- | --- | --- |
| мир 288×208 | ~930 ms | ~370 ms |
| эрозия | 396 ms (17 проходов) | ~90 ms (10 проходов) |
| растительность | — | ~90 ms на 112k деревьев |

Что именно убрано (`npm run bench:world` показывает стадии):

1. **Сортировки.** Каждый проход эрозии сортирует десятки тысяч клеток по
   высоте, и с компаратором это была самая дорогая операция во всей генерации —
   дороже, чем сама гидрология вокруг неё. Заменено поразрядной сортировкой по
   битовому представлению float (`world/sort.ts`), это линейное время вместо
   дерева сравнений.
2. **Озёра внутри цикла эрозии.** Группировка бассейнов с уровнем, точкой
   перелива и стоком нужна ровно один раз — в конце. Эрозия её не читала и всё
   равно считала каждый проход.
3. **Аллокации.** Все буферы гидрологии живут в одном `HydrologyWorkspace` и
   переиспользуются, а не создаются заново десять раз за проход.
4. **Проходы эрозии.** 17 → 10. Сеть долин прорезается первыми несколькими
   проходами, остальные её только сглаживают. Ручка осталась: `?erosion=20`.

Ключи по клетке (`"12,34"` и `Map`) заменены на индексы — генератор больше
нигде не строит строк.

## Что на карте

- **Рельеф и вода** — один vertex-colored меш, семь вершин на гекс. Центры
  морских и озёрных клеток лежат на уровне своей воды, а общие береговые углы
  опускают сушу к тому же уровню. Поэтому отдельная плоскость не пересекает
  землю, поверхность не мерцает и берег остаётся герметичным.
- **Реки** — лентой по центрам клеток, ширина от водосбора. Реки по *сторонам*
  гексов, как в Civ, — это отдельная работа по дуальной сетке; данные для неё
  уже есть.
- **Деревья и кусты** — thin instances, три оттенка листвы задаются
  per-instance цветом, а не тремя материалами. Расстановка живёт в
  `world/vegetation.ts` и хеширована от клетки: лес на одном гексе можно
  пересадить (пожар, дорога, город), не сдвинув ни одного дерева на соседних.
- **Тени** — солнце с фиксированным ortho-боксом, который едет за камерой.
  Тени резкие там, куда смотрит игрок, и их нет дальше `?shadowspan`. Это
  осознанный размен: одна карта теней, растянутая на весь мир в 500 единиц,
  не даёт ничего видимого.

`?res=1` по одному, `?backend=webgl` против `?backend=webgpu` при прочих равных.

## HUD

Левая панель меряет то, чего не показывает обычный счётчик кадров:

- **интервалы между показанными кадрами** (p50/p95/p99), а не темп сабмита.
  `scene.render()` на WebGPU только отправляет команды и не ждёт GPU;
- **реальное время GPU** через timestamp queries. Если адаптер их не даёт,
  строка честно пишет «недоступно», а не подставляет время CPU;
- предупреждение, когда GPU не успевает за темпом сабмита. Это то состояние,
  где счётчик показывает 60 fps, а картинка стоит.

## Проверки

```text
npm run check          # границы слоёв + типы + сборка сцены
npm run bench:world    # генерация мира по стадиям, без браузера
npm run check:scene    # вся сцена на NullEngine: меши, буферы, три кадра
```

`check:scene` собирает мир, рельеф, воду, реки, растительность, тени, камеру и
рисует три кадра на `NullEngine`. Он ловит целый класс ошибок, которые иначе
находятся только глазами в консоли: неимпортированный side-effect модуль
(`thinInstanceSetBuffer`, который молча ничего не делает; `createPickingRay`,
который бросает из цикла рендера), пустые буферы, NaN в геометрии, разъехавшиеся
углы гексов. Чего он не ловит: компиляцию шейдеров, WebGPU-пайплайны и всё, на
что надо смотреть.

## Известные ограничения

- **Тени на WebGPU.** На Babylon 9.21.0 нативный WGSL shadow-вариант собирал
  невалидный пайплайн для thin-instance кастеров на Dawn, и обходом был
  `forceGLSL`. На 9.21.2 ломается уже GLSL-путь: shadow-шейдер уходит в glslang
  и падает с «GLSL compilation failed» до первого кадра. Поэтому по умолчанию
  теперь нативный WGSL, а старый путь — `?shadowglsl=1`. Если тени пропадут
  после обновления Babylon, проверять надо это место.
- **Мир — цилиндр, а рисуется плоским.** Генератор замыкает карту по западу и
  востоку, рендер этого не делает: на левом и правом краю карты стык. Полярные
  ряды — океан, север и юг замыкать не нужно.
- **Тумана нет, дальность максимальная.** Весь мир держится в кадре целиком.
  Это потолок, а не паритет с игрой, в которой будет туман войны.
- **Моделей на карте пока нет.** Пайплайн для них написан и задокументирован —
  `render/models.ts`, GLB через `LoadAssetContainerAsync` с выпрямлением
  иерархии и запеканием трансформа в вершины, дальше thin instances. Число
  draw call равно числу мешей *внутри* модели, а не числу построек, поэтому
  разбиение ассета на меньшее количество мешей ценнее любого куллинга.
